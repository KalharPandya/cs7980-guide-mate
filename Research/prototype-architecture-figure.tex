\caption{Architecture of the guide-robot prototype. A visitor's typed or spoken
request is transcribed, answered by a Bedrock-hosted Claude Sonnet agent grounded
in a campus knowledge base, and may be turned into a robot command that travels
over AWS IoT Core (MQTT, QoS 1, SigV4 from the service and X.509 mutual TLS from
the robot) to an on-robot bridge, the only component that actuates the base.
Numbered circles mark five independent checks, each failing closed: (1) the
session must hold the robot lock, granted only by an authenticated operator;
(2) the model may emit only a closed, schema-validated vocabulary of three
emotes, two tricks and a stop; (3) the device shadow must have armed motion,
whose defaults are disarmed and dry-run; (4) the dock guard refuses any
non-docking command while the robot is docked or its dock state is unknown;
(5) every primitive is clamped to 0.15\,m/s, 1.5\,rad/s and 30\,s before any
velocity is published. Dashed components are the mapping and navigation stack: they run
on the same robot but are brought up separately and are not reachable from the
deployed language front end.}
