## Mission (next 24 hours)
Implement the **dog agent POC end to end**: an LLM agent with a dog persona that chats with

## Architecture decisions (all approved by Kalhar, 2026-07-05)
| Decision | Choice |
|---|---|
| Agent hosting | Own loop, one **Python/FastAPI container** (laptop now → EC2 later). NOT Lambda, NOT Bedrock Agents (rejected: no persistent MQTT, no live acks, cold starts). |
| LLM | **Bedrock, Claude Sonnet 4.6**, via Strands Agents (Converse API). |
| Robot link | **AWS IoT Core MQTT**. Topics `guidemate/turtlebot468/cmd` + `/status`, QoS 1. Cloud publishes **named primitives only** — never raw velocities. |
| On-robot | New **agent bridge node** (AWS IoT Device SDK + rclpy): executes emote/motion choreographies locally as capped `cmd_vel` sequences; acks by `cmd_id`. |
| Safety | **Default-deny motion** via IoT **Device Shadow** (`motion_enabled=false` default, missing shadow = false) + **dock guard** (refuse motion while docked) + `dry_run` mode. Kill switch works even if the agent service dies. |
| Admin panel | Inside the FastAPI container: `/admin` static UI + `/api/admin/*`, single-token auth. Agent-tier flags in SQLite (gate which tools the model sees); robot-tier flags via Device Shadow. |
| Knowledge | **Bedrock Knowledge Bases** (S3 docs → managed RAG, **S3 Vectors** backend — NOT OpenSearch Serverless, cost). Agent tool `retrieve_kb`; admin panel gets upload/list/sync tab. |
| Emote vocabulary (initial) | `no` = rotate CW/CCW, `yes` = forward/back nod, `happy` = wiggle/random; motions: `circle`, `spin`, `stop`. Extensible library on the bridge. |

**Long-term vision (design for, don't build):** general-purpose org agent; semantic campus
locations (name → map coords, always structured lookup, never vector RAG); "see the map"
(S3 snapshots); robot 436; guide missions.

## ⚠️ Robot safety — absolute rules
Robot 468 is **docked and unobserved**. It is **not allowed to move**. No `cmd_vel`, no
undock/dock/navigate, no motion of any kind until a human observer is present and enables
motion. Everything except final motion tests is designed to run in this state (see the
spec's *No-motion verification checklist*). Read-only probing: no service restarts, no
reboots, no `pkill`, no config changes on the Pi without explicit need.
